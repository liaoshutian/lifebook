# 001：记录明细使用版本化结构数据

- 状态：已采纳
- 日期：2026-07-30

## 背景

`LifeEntry` 原本只有数值、时长、评分和备注。为每个内置事件持续增加可选列，会让核心模型不断膨胀，也会让不相关字段出现在所有记录中；完全自由的键值文本则无法稳定地校验、展示和导出。

## 决策

通用字段继续直接保存在 `LifeEntry` 中。事件专属的记录明细使用 `EntryDetails` 保存为带版本号的结构数据，由 `EntryDetailSchema` 定义稳定字段标识、输入类型、选项与中文展示名称。

每条记录保存当时的明细值；事件定义只描述“可以记录什么”，不持有某次记录的数据。

## 结果

- 新增内置字段不需要继续扩张 `LifeEntry` 的列。
- 表单、历史展示、导出和 AI 上下文共享同一套字段语义。
- 旧记录没有明细数据时仍可直接读取。
- 明细不适合直接做数据库列级查询；未来若需要按体温等字段进行大量筛选或聚合，应迁移为独立的索引模型。
